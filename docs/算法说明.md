# 算法说明

## 1. 特征

每支球队从最近 10 场中提取：

- `points_per_game`
- `goals_for_per_game` / `goals_against_per_game`
- 主场、客场拆分 PPG（样本不足 3 场时不用）
- 赢盘率、大球率（只用于报告上下文）

缺少往绩时按中性值处理，并把 `quality_score` 降低。

另有一个可选 H2H 特征：当双方历史交锋 >= 3 场时，按“当前主队视角”计算 H2H PPG：

```text
h2h_ppg = (主队胜场 * 3 + 平局) / H2H 总场次
h2h_gap = clamp((h2h_ppg - 1.30) * 0.35, -0.30, 0.30)
```

`h2h_gap` 只以 0.10 / 0.10 的系数轻微修正主客 lambda。H2H 样本小且跨年份/跨赛事，因此不参与 `quality_score`，也不会推翻市场方向；报告会单独展示“交锋”列。

## 2. 泊松预期进球

参考项目量化模型的核心公式是：

```text
home_lambda = 1.34
            + (home_attack - 1.45) * 0.34
            + (away_defense - 1.10) * 0.24
            + form_gap * 0.16
            + goal_diff_gap * 0.10
            + home_away_split_gap * 0.14
            + h2h_gap * 0.10
```

away_lambda 使用同一组差异特征的负向权重。MVP 没有拿到参考项目的联赛排名/身价/xG 特征，因此刻意降低独立模型的影响；H2H 仅在 >= 3 场时以很小的权重参与。

求出 lambda 后枚举 `0..8` 比分网格，得到：

- 主胜/平/客胜概率
- 最可能比分
- 亚盘让球覆盖概率（含走水）
- 大小球大/小/走水概率

## 3. 市场锚定

参考项目自己的结算回测结论是：独立模型单独预测普遍不如市场；最终概率应该向市场收缩。MVP 采用：

```text
final = model_prob * w + market_prob * (1-w)
w = 0.12 + 0.04 * history_coverage
```

完整往绩时 `w = 0.16`，无往绩时 `w = 0.12`。市场概率优先使用 `odds.xml` 的 `gl avg`，缺失时用欧赔去水。

这样模型负责偏离判断，市场负责方向锚点，避免跨联赛往绩噪声把概率拉离定价太远。

## 4. 动作门禁

- `主推`：模型与市场方向一致、最终概率 >= 52%、次优概率差 >= 12%，且数据质量 >= 0.55。
- `轻仓`：方向一致、最终概率 >= 38%，概率差 >= 4%。
- `观望`：无欧赔/市场、方向分歧、概率过低或数据质量不足。

方向分歧会在报告中写明，例如“模型看客胜，市场看主胜”。

## 5. 赔率与盘口分析

胜平负推荐之外，`odds_analysis` 再对每个市场做一次“盘口倾向 vs 模型比分覆盖”的两向分析，输出推荐方向、融合概率、动作和 EV：

### 欧赔市场

- 只有当拿到真实欧赔（任一 > 1.01）时 `available=true`；无欧赔场次不会显示默认的 `33.3% / 33.3% / 33.3%`，而是标为“欧赔/市场：无，模型仅供方向参考”。
- 展示去水后的主/平/客概率，并对照模型方向与最终方向；胜平负动作仍沿用主模型的门禁（见第 4 节）。

### 亚盘让球

- 市场侧：水位较低一方视为庄家/市场倾向；水位同高或缺失时，按让球方向回落（主队让球则看客队受让方）。
- 模型侧：把泊松比分分布按让球线换算为“主队赢盘/客队赢盘/走水”，再归一化得到主队覆盖倾向。
- 融合：`final = 85% * 市场水位概率 + 15% * 模型覆盖概率`。
- 门禁：市场与模型同向且最终概率 >= 65%、边距 >= 28% 为 `主推`；同向且 >= 55%、边距 >= 10% 为 `轻仓`；否则 `观望`。

### 大小球

- 同样以低水侧为市场倾向，模型侧由比分分布按大小盘口切出大/小/走水。
- 融合与门禁阈值与亚盘一致，另外给出大球/小球 EV 供参考。

### 整期推荐汇总

Markdown 报告首屏按 `主推 > 轻仓 > 观望` 排列所有场次，同时列出胜平负、亚盘让球、大小盘三个市场的建议；CSV 增加“让球建议/大小建议”两列，控制台摘要也显示让球与大小的实际建议。

## 6. 初盘/即时异动提示

每场比赛额外抓取 Nowscore 移动分析页的“赛前指数”，只消费其中的亚洲盘让球行：同一公司给出初盘和即时盘，先把 Nowscore 正负号换算成本项目的“主队视角”让球数，再对比变化。

- 让球线变化按上盘（让球方）让球数计算：变化 >= 0.25 记为“关注”，>= 0.5 记为“重点关注”。
- 上盘让球增加记为“升盘”，提示倾向上盘/让球方赢盘。客队让球加深同样是升盘，不再称为退盘。
- 上盘让球减少记为“降盘”，提示倾向下盘/受让方赢盘。
- 让球线未变但初盘/即时盘受注水位反转，或任一侧水位变动 >= 0.08，也记为“关注”，提示市场水位异动。

大小盘和欧赔只继续参与各自盘口分析或市场概率，不再触发变盘提醒。达到关注线时，Markdown 报告在“整期推荐汇总”后给出“变盘异动提醒”，CSV 增加“变盘异动/变盘说明”列，控制台也在摘要后打印异动场次。提示只用于提醒亚盘让球被资金/公司调价，不直接改变胜平负或亚盘/大小盘的推荐动作。

## 7. 校验口径

- 单测覆盖盘口文本换算、总进球概率、亚盘覆盖概率、概率归一化、Titan/Nowscore H2H 方向归一化。
- 初盘/即时解析和异动判定由 `tests/test_odds_movement.py` 覆盖，含 Nowscore 正负盘口换算、主让升/降盘、客让升/降盘、水位反转，以及大小盘变化不会误触发的样例。
- 端到端验证使用当前期 `26120` 的真实抓取结果。
- 正确性只到“数据解析和数学可复现”层面；长期命中率需要赛后结果反馈表才能验证，不在当前 MVP 范围内。

# 交接说明

> 最后更新：2026-09-29。接手前先跑 `python -m unittest discover -s tests`（应 71 项全过）和本文的「快速验证」。

## 1. 项目一句话

轻量级足球胜负彩分析 MVP：抓最新一期胜负彩 → 往绩/H2H → 泊松模型 + 市场先验 → 欧赔/亚盘/大小球分析 → 亚盘让球 + 大小盘异动提醒 → SQLite + HTML 报告 → 赛后复盘统计推荐命中率。技术栈是纯 Python + `requests`/`beautifulsoup4`，**没有 Web 框架、没有浏览器依赖**，PyInstaller 打单文件 exe。

```powershell
python run.py --cache-dir cache                      # 抓最新一期并生成报告
python run.py --issue 26129 --cache-dir cache --no-db   # 用缓存重跑历史期
python run.py query --serve                          # 异动查询页（自选 8765 附近空闲端口）
python run.py review --issue 26133 --refresh         # 赛后复盘：刷新比分并统计推荐命中率
python run.py review --trend                         # 跨期命中率趋势
python -m unittest discover -s tests                 # 测试
```

## 2. 功能全集（截至 2026-09-29）

- **自动抓取最新一期**：不传 `--issue` 时自动识别最新开售期；自动模式下当期列表/竞彩列表/`odds.xml` 不走缓存，保证不残留旧期。
- **往绩 + H2H**：liansai 近 10 场；Titan 赛程映射到 match id，Nowscore 移动端抓历史交锋（Titan 桌面页 442 不可用，靠镜像）。
- **泊松模型 + 市场收缩**：独立进球分布 + 去水概率融合，H2H ≥ 3 场时做小幅 `h2h_gap` 修正。
- **欧赔/亚盘/大小球分析**：`odds_analysis.py` 输出主推/轻仓/观望；亚盘/大小球推荐用模型比分概率覆盖盘口概率。
- **大小球双来源兜底**（09-28）：`odds.xml` 的 `dxq` 优先；缺失时回落 Nowscore 赛前指数即时盘，零新增网络请求；报告标注来源（`澳门`/`赛前指数`），异动提醒仍只消费亚盘。
- **大模型解读（可选，09-29）**：`analyze --narrate` 为达到关注线的异动场次生成 3-4 句综合解读（近况与当前对手过去对战优先，再解读盘口异动），挂在 HTML 异动表行下方；需 `LLM_API_KEY` 环境变量（可选 `LLM_BASE_URL`/`LLM_MODEL` 指向 DeepSeek 等），无 Key 或请求失败时静默回退，不影响报告生成。解读只引用已采集的近况、当前对手过去对战、盘口与模型数据，不产生新的投注建议，也不进 exe 主路径。
- **异动提醒**：消费亚盘让球初盘/即时盘（升盘/降盘/水位反转/水位摆动）+ 大小盘初盘/即时盘（大小盘升降 ±0.25 关注、±0.5 重点关注，水位摆动 ±0.08）；欧赔不触发。`kind` 字段亚盘优先，亚盘无信号时取大小盘 kind。
- **倾向列**（09-29 完善）：亚盘异动提示里的 `lean` 已改用真实球队名（如"倾向葡萄牙赢盘"），pipeline 抓取盘口异动时传入 `home_team`/`away_team`；查询页/报告页的倾向列截掉括号后缀显示纯球队名，兼容旧数据。
- **本地 SQLite 异动库**：每期快照 + 异动明细入库，支持 `query` 命令行与 `query --serve` 浏览器查询页（含大小球列、升降盘配色高亮）。
- **查询页报告入口**（09-30）：`query --serve` 查询页在“查询”按钮旁新增“分析报告”按钮，选择期号后一键在新标签打开该期 HTML 报告；服务端通过 `/report/<文件名>` 路由直接返回 `reports/` 下的 `issue_<期号>_<时间戳>.html`（路径穿越返回 404）；期号与报告文件由 `report_index.build_issue_report_index` 按期号取最新一份匹配；无报告时按钮置灰并提示。
- **赛后复盘**（09-28）：`review` 子命令刷新最终比分并统计亚盘/大小球主推/轻仓命中率（走水不计）；`review --trend` 跨期命中率趋势与环比，作为后续反馈学习的净基线。

## 4. 数据源现状（重要，避免重复踩坑）

| 源 | 地址 | 实测状态 |
|---|---|---|
| SFC 列表 | `trade.500.com/sfc/` | 可用。`data-asian` 14/14 有值；`data-bjpl`（列表欧赔）当前全空 |
| odds.xml | `www.500.com/static/public/jczq/xml/odds/odds.xml` | **可用，但必须带 Referer**（`https://trade.500.com/jczq/`）。裸 requests 无 Referer 偶发拿到 ~990 字节挑战页 |

| Nowscore 移动端 | `m.nowscore.com/Analy/Analysis/{mid}.htm` | **可用，须带 Referer**（`https://m.titan007.com/`）。裸 requests 会遇 10054 连接重置 |

一句话：**所有"数据源挂了"的表象，十有八九是没带 Referer 或遇到了间歇挑战**，先别急着找替代源。`Fetcher._additional_headers` 已按域名处理好 Referer，直接用 Fetcher 就行。

### 缓存防毒化（09-28）

[http.py](../football_analysis/http.py) 的 `_is_challenge` 识别 EdgeOne 反爬 200 + JS 挑战页（特征 `EO_Bot_Ssid`）：拒绝写入缓存、直接抛错，交给 pipeline 既有 `except` 降级。以前 `fetch` 在解析前就存缓存，一次挑战会污染 `odds_xml:current` 之类的键，让后续重跑一直读到坏数据。

### H2H 跨天赛程合并（09-28）

`fetch_issue_schedule` 以前只查 3 天中第 1 天的 BF Next 赛程就返回，导致 26134 这类跨周末的 14 场里第 8-14 场（周六比赛）映射不到 Titan match id，H2H 覆盖 0/14。现改为**遍历 3 天全部**赛程合并，配合 `match_no_to_tian_match`（[h2h.py](../football_analysis/h2h.py)）做 team-id fallback，H2H 恢复 14/14。

**注意**：`build_sfc_match_map` 对同一天内多期胜负彩共存的情况（如 26133 和 26134 都在 09-30 开售）依赖 `issue` 后缀匹配，不会跨期混用。

## 8. 已知边界与下一步

**已知边界**

- `odds.xml` 与竞彩开放场次绑定，覆盖不到非竞彩的胜负彩场次——现在由赛前指数回落补上；仍缺的只有连 Titan 赛程都映射不上的极少数场次（它们连 H2H 也没有）。
- 竞彩列表改版是**持续观察项**：当前可解析，但 `info_match_id` 映射和 odds.xml 的 match id 对齐依赖该页；一旦再次改版，回落详情页只补球队 ID，**欧赔/亚盘的多公司对齐能力会下降**，届时优先修 `parse_jczq_html`。
- 异动提醒消费亚盘让球 + 大小盘初盘/即时盘；欧赔不触发提醒。
- Nowscore"赛前指数"是抓取时刻的快照，不是完整逐笔时间线；要看盘中变化需在**不同时间**多次运行并保留各次 HTML/JSON 报告。
- 模型输出是研究参考，不是投注承诺。

**数据沉淀与下一步**

1. 每期开始前 `analyze` 一次、结束后 `review --refresh` 回写比分（如 26133 期已按此流程完成）。
2. 累计 ≥ 30 期后启动阈值回测（`ASIAN_LINE_WATCH` / `...WATER_WATCH` / `...TOTAL_LINE_WATCH`），用历史命中数据回填更优取值；前期样本少只看趋势，不刻意调参。
3. 浏览器抓取 `daxiao-` 页的方案已评估为不划算（与 MVP 轻量定位冲突），已取消。
4. 软信息采集（伤停/战意/赛制）是下一个高价值但高成本方向，仅属探索；当前 `--narrate` 只解释已采集数据，不产出新的软信息。推荐先等快照累计 ≥ 30 期后结合错误归因再评估，优先在 `quality_score` 低的“观望”场次试点。
5. 生产部署与多公司完整赔率时间线尚未做，不在当前范围内。

升级链路（[updater.py](../updater.py) + [update_installer.py](../update_installer.py)）：

- 查询页「设置 → 软件升级」：`GET /update/check` 读 `latest.json` 比版本号；
  `POST /update/install` 下载完整包、SHA-256 校验（失败即删包报错，不替换），
  再启动同目录 `足球更新器.exe --archive <包> --target <主程序> --restart`。
- `足球更新器.exe`（入口 `run_updater.py`，spec `足球更新器.spec`）：
  等主程序解锁（PE 写锁探测）→ 从 zip 取出新主程序暂存 `.new` → 原 exe 挪 `.old` →
  转正 → 写 `.fa_update_restart` marker 并重启。`data/`、`cache/` 等本地数据一律不动。
- 清单地址可用环境变量 `FA_UPDATE_MANIFEST_URL` 覆盖；默认指向
  `https://github.com/jackybee6933-code/zucaikan/releases/latest/download/latest.json`。
- 测试：[tests/test_updater.py](../tests/test_updater.py) 4 项（版本比较、清单校验、
  SHA-256 校验、更新器替换演练）。

已知边界：

- `latest.json` 的 `url` 必须对中文资产名百分号编码（`create_latest_manifest.py` 已处理），
  否则 `releases/download` 返回 404。
- 完整包必须包含 `足球更新器.exe`（`make_package.py` 与 `make_release.py` 都已带）；
  缺它时 exe 内一键升级会提示手动解压新完整包。
- 主程序对 `.fa_update_restart` marker 的消费尚未实现（可选优化），重启动作目前由更新器直接完成。

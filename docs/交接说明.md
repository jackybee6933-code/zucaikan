## 1. 项目一句话

轻量级足球胜负彩分析 MVP：抓最新一期胜负彩 → 往绩/H2H → 泊松模型 + 市场先验 → 欧赔/亚盘/大小球分析 → 亚盘异动提醒 → SQLite + HTML/MD/CSV/JSON 报告。技术栈是纯 Python 标准库 + `requests`/`beautifulsoup4`，**没有 Web 框架、没有浏览器依赖**，PyInstaller 打单文件 exe。

```powershell
python run.py --cache-dir cache              # 抓最新一期并生成报告
python run.py --issue 26129 --cache-dir cache --no-db   # 用缓存重跑历史期
python run.py query --serve                  # 起异动查询页（自动选 8765 附近空闲端口）
python -m unittest discover -s tests         # 测试
```

## 2. 本期变更（2026-09-28）

### 大小球：双来源兜底

以前大小球只认 `odds.xml` 的 `dxq` 节点，它覆盖不到的场次（只进胜负彩、不进竞彩池）直接判"无市场"。现在：

- [pipeline.py](../football_analysis/pipeline.py) 新增 `_total_from_movement`：odds.xml 缺失时回落到同一场已抓好的 Nowscore 赛前指数即时盘（`odds_movement["total"]["current"]`），**零新增网络请求**。
- `market["total"]["source"]` 记录来源；odds.xml 优先（取公司标签如"澳门"），回落场次标"赛前指数"。
- 报告大小球列统一走 [browser_report.py](../football_analysis/browser_report.py) 的 `_total_display`，显示成 `2.5/3 0.95/0.92（赛前指数）`，来源一目了然。

**注意**：`_total_display` 曾经是零调用（历史遗留），HTML 两张表实际用的是 `_movement_total_display`，导致来源后缀一直没显示。本次已把两处调用切到 `_total_display` 并删除死代码，同步更新了 3 个固化旧口径的测试。异动提醒**仍只消费亚盘**（既定边界，没动）。

### 缓存防毒化

[http.py](../football_analysis/http.py) 新增 `_is_challenge`：EdgeOne 反爬返回 200 + JS 挑战脚本（特征 `EO_Bot_Ssid`），现在会被识别并**拒绝写入缓存**、直接抛错，交给 pipeline 既有的 `except` 降级。以前 `fetch` 在解析前就存缓存，一次挑战就会污染 `odds_xml:current` 之类的键，让后续重跑一直读到坏数据。

### H2H 多日赛程修复

`fetch_issue_schedule` 以前只查 3 天中**第 1 天**的 BF Next 赛程就返回，导致 26134 这类跨周末的 14 场里第 8-14 场（周六比赛）映射不到 Titan match id，H2H 覆盖 0/14。现改为跨 3 天**全部**赛程合并，再配合 `match_no_to_tian_match`（h2h.py）做 team-id fallback，H2H 恢复 14/14。

**注意**：`build_sfc_match_map` 对同一天内多期胜负彩共存的情况（比如 26133 和 26134 都在 09-30 开售）依赖 `issue` 后缀匹配，不会跨期混用。

### 文档

[数据源与限制.md](数据源与限制.md) 补充了竞彩列表改版、odds.xml 间歇挑战的实测结论。

## 3. 数据源现状（重要，避免重复踩坑）

| 源 | 地址 | 实测状态 |
|---|---|---|
| SFC 列表 | `trade.500.com/sfc/` | 可用。`data-asian` 14/14 有值；`data-bjpl`（列表欧赔）当前全空 |
| odds.xml | `www.500.com/static/public/jczq/xml/odds/odds.xml` | **可用，但必须带 Referer**。Fetcher 带 `Referer: https://trade.500.com/jczq/` + 重试，实测连续 3 次稳定；裸 `requests` 无 Referer 偶发拿到约 990 字节挑战页 |
| 竞彩列表 | `trade.500.com/jczq/?playid=312&g=2` | **已改版为 JS 渲染**，`parse_jczq_html` 拿到 0 行。球队 ID/队名自动回落到 500 详情页补全 |
| 500 详情页 | `live.500.com/detail.php?fid={fid}` | 可用，但**只含球队 ID 与比分，不含任何赔率/盘口** |
| Nowscore 移动页 | `m.nowscore.com/Analy/Analysis/{mid}.htm` | **可用，须带 Referer**（`Referer: https://m.titan007.com/`）。裸 requests 会遇到连接重置（10054） |
| Titan 桌面页 | `zq.titan007.com/analysis/{mid}cn.htm` | 442，不可用；H2H 与赛前指数都靠移动页 |
| `odds.500.com/fenxi/*` | 含 `daxiao-{fid}.shtml` | EdgeOne 强制 JS 校验，移动 UA / Referer / `yapage` 变体均无效。多公司大小球改由 odds.xml 提供 |

一句话：**所有"数据源挂了"的表象，十有八九是没带 Referer 或遇到了间歇挑战**，先别急着找替代源。`Fetcher._additional_headers` 已按域名处理好 Referer，直接用 Fetcher 就行。

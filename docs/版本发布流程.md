# 版本发布流程

版本升级前先保留当前可交付版本，避免新版本打包失败后无法回退。

```powershell
python tools/release.py 1.3.36
```

`release.py` 会在修改源码版本号前自动把 `dist/` 中已有的发布文件归档到：

```text
dist/history/football_analysis_v<旧版本>_<时间>.zip
```

归档内容包括主程序、更新器、安装包、完整包、`latest.json` 和必要的抓取工具脚本；运行缓存、数据库、报告和 `history` 目录本身不会打进归档。

也可以单独执行归档：

```powershell
python tools/archive_release.py
```

如果是第一次发布、`dist/` 还没有可交付文件，版本同步会提示并跳过归档。

设置中的版本升级优先使用普通发布链接。默认更新清单访问失败时，通过 GitHub Releases API 下载 `latest.json`；安装包下载重试失败时，按原安装包所属的发布标签查找同一资源，通过 API 重试下载。两条下载通路都校验清单中的 SHA-256，失败时不会安装，也不会改下 ZIP 包。公开资源无需用户配置 GitHub Token；API 下载仍可能跳转到文件服务器，其可达性受本地网络影响。

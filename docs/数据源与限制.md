# 数据源与限制

## SFC 胜负彩列表

- URL：`https://trade.500.com/sfc/`
- 历史期：`https://trade.500.com/sfc/?expect={issue}`
- 每行 `tr.bet-tb-tr` 自带：
  - `data-bjpl`：列表欧赔（部分场次为空）
  - `data-asian`：亚盘水位/盘口/水位
  - `data-pjgl`：胜/平/负投注比例
  - `td-data a` 中的 `shuju-{fixture_id}.shtml`
- SFC 页队名经常是短名，例如“雅典”“林茨”，需要竞彩列表或详情页补全。

## 竞彩列表作为映射层

- URL：`https://trade.500.com/jczq/?playid=312&g=2`
- 每行关键字段：
  - `data-fixtureid`：与 SFC 详情页 ID 相同
  - `data-infomatchid`：对应 `odds.xml` 的 `match id`
  - `data-homeid` / `data-awayid`：liansai 球队 ID
  - `.team-l` / `.team-r`：完整队名
- 该页当前约 23 场，小于 SFC 当期 14 场覆盖范围，原因主要是部分足彩场次尚未进入竞彩销售池。
- 实测 2026-09-28 起该页返回 JS 渲染的空壳（`tr.bet-tb-tr` 0 行），`parse_jczq_html` 拿不到场次；此时球队 ID/队名自动回落到 500 详情页补全，而详情页只含球队 ID 与比分，不含任何赔率/盘口。

## odds.xml

- URL：`https://www.500.com/static/public/jczq/xml/odds/odds.xml`
- 每场 XML 字段：

```xml
<match id="165721">
  <europe avg="1.77,3.88,4.28"/>
  <asian am="0.940,半球/一球,0.900"/>
  <dxq am="1.00,3,0.80"/>
  <gl avg="53.47,24.39,22.14"/>
  <rq avg="2.91,3.68,2.02"/>
</match>
```

- `asian am`：主队水位 / 让球盘口 / 客队水位
- `dxq am`：大球水位 / 大小盘口 / 小球水位
- `europe avg`：欧赔均值
- `gl avg`：主/平/客百分比，合计基本等于 100%，比直接对欧赔去水更干净，本系统优先使用它作为市场先验。
- `rq avg`：让球 3-way 赔率，保留在 JSON 中，暂不参与胜负平模型，只在盘口分析里辅助判断让球方倾向。

盘口文本方向统一按“主队视角”换算：例如“半球/一球”表示主队让 0.75，“受半球/一球”表示主队受让 0.75。

## liansai 球队页

- URL：`https://liansai.500.com/team/{team_id}/`
- 页面编码为 GB2312/GB18030，部分字节不合法，需要容错解码。
- `table.lcur_race_list` 的每行字段：

```text
赛事 | 比赛时间 | 主队 | 比分 | 客队 | 赛果 | 盘路 | 大小 | 分析
```

- “赛果”是相对当前球队的胜/平/负；
- “盘路”是相对亚盘水位盈亏：赢/输/走；
- “大小”是相对大小盘：大/小。
- 页面默认展示最近 10 场，不保证全赛季；其中包含友谊赛/杯赛，跨联赛直接比进球数有噪声，这是模型把市场保持为强先验的原因之一。

## Titan 赛程日期页（场次映射）

- URL：`https://bf.titan007.com/football/Next_{yyyymmdd}.htm`
- 编码为 GB2312/GB18030，一页覆盖当天 12:00 起到次日中午前后的赛程。
- 每个 `tr` 的 `sid` 就是 Titan 比赛 ID；页尾 JS 同时包含：

```text
zuCaiSchedule = "3073215,3073135,...|120-01,120-02,..."
jinZuSchedule = "2929718,3073215,...|周二001,周二002,..."
```

- 胜负彩映射规则：`120-01` 表示 500 期号 `26120` 的第 1 场，`120-02` 表示第 2 场，依此类推。`h2h.py` 用 SFC 最早开赛时间推算候选日期，再按这个 `zuCaiSchedule` 建立 `match_no -> Titan match_id`。
- 该页同样可用作“未进竞彩池的 SFC 场次”的映射来源，例如只进胜负彩不进竞彩的英冠/英联杯场次也能拿到 Titan ID。

## Titan 桌面分析页 / Nowscore 移动页（H2H）

- 主 URL：`https://zq.titan007.com/analysis/{match_id}cn.htm`
- 镜像 URL：`https://m.nowscore.com/Analy/Analysis/{match_id}.htm`
- Titan 桌面页为 UTF-8 文本，内含：

```text
var h2h_home = 82;
var h2h_away = 152;
var v_data = [[日期, 联赛ID, 联赛名, ..., 主队ID, 主队, 客队ID, 客队, 比分, ...], ...];
```

- `v_data` 为空数组表示系统里确实没有双方过往交锋，不是抓取失败；桌面页不可达时自动换移动页解析 `#vsMatches` 表格。
- `h2h.py` 会把历史比分统一换算成“当前主队视角”：主胜/平/客胜、主队进球/失球、逐场记录。这个方向只用于统计和展示，模型只把它当作很小的泊松倾斜。

## Nowscore 移动页

- URL：`https://m.nowscore.com/Analy/Analysis/{match_id}.htm`
- 编码为 UTF-8，移动版与桌面版信息互补。本 MVP 把 Nowscore 作为桌面页超时/拦截后的兜底源，避免单场偶发失败影响整期。

## Nowscore 赛前指数（初盘/即时盘）

- 同一移动分析页内包含“赛前指数”表，分别有欧赔、亚盘、大小盘行；本系统的变盘异动提醒只消费亚盘让球行。
  - `欧`：主胜 / 平 / 客胜
  - `亚`：主队水位 / 让球盘 / 客队水位
  - `大`：大球水位 / 大小盘 / 小球水位
- 每行前三个单元格带 `class="firstOdds"`，是初盘；后三个单元格是抓取时刻的即时盘。
- 亚盘文本是 Nowscore 的符号口径：带前导负号表示主队受让（如 `-0.5/1`），不带表示主队让球（如 `0.5/1`）。`odds_movement.py` 统一换算成本项目“主队视角”数值后再比较变化。
- 该表来自默认公司，是“同一来源”的初盘/即时对比；它反映抓取时刻相对市场开盘的变化，多次定时抓取即可看到不同时间点的即时盘。

## 当前抓取限制

1. `odds.500.com/fenxi/*` 被 EdgeOne 类 JS 校验拦截，单凭 `requests` 拿不到完整 shuju/欧指/亚盘详情页。本系统的 shuju 替代源是 liansai 球队页。
   - 实测 `daxiao-{fid}.shtml`（多公司大小球）同样被拦截：移动 UA、带 Referer、`?yapage=1` 三种变体均只返回约 990 字节的 `EO_Bot_Ssid` 挑战脚本，无页面内容，需要执行 JS 才能绕过。
   - 多公司大小球改由 `odds.xml` 的 `dxq` 节点提供（该静态 XML 不拦截）；`odds.xml` 覆盖不到的非竞彩场次，再回落到 Nowscore 赛前指数的即时大小球盘（见 `pipeline._total_from_movement`）。
2. 双方 H2H 已通过 Titan 桌面页 + Nowscore 移动页接入；两个域名都可能做限流/改版，单场失败会记录 warning，报告不阻断。
3. `odds.xml` 与竞彩开放场次绑定，不能作为所有胜负彩场次的完整市场数据源。该端点受 EdgeOne 间歇性挑战：项目 `Fetcher` 对它带 `Referer: https://trade.500.com/jczq/` 并重试，实测稳定；裸 `requests` 无 Referer 时会拿到约 990 字节的挑战脚本。`Fetcher` 现在会识别挑战页并拒绝写入缓存（`_is_challenge`），避免无效内容毒化 `odds_xml:current` 导致后续重跑一直读到坏数据。
4. 上游改版会破坏解析器，所以抓取层保留原始页面缓存，便于重跑定位。
5. Nowscore“赛前指数”提供初盘和抓取时刻的即时盘，能覆盖亚洲盘让球变盘与水位异动；它不提供中间每次变盘时间线，若需要完整变化序列可扩展抓 `/Analy/OddsDetail` 的历史行。
6. “低水 = 市场倾向”只是可复现的简易启发式；异动提示阈值（让球线 0.25/0.5、水位 0.08）是研究口径，不是预测胜率。

## 自动最新期与缓存

- 不传 `--issue` 时，程序访问 `https://trade.500.com/sfc/`，从页面 `selected` 的期号识别当前最新开售期。
- 自动模式下，`sfc:https://trade.500.com/sfc/`、`jczq:current`、`odds_xml:current` 三个键不读取也不写入缓存，防止隔期后继续使用旧列表或旧市场快照。
- 显式传 `--issue 26120` 时上述三个键仍可读写缓存，便于重复复测同一历史期。
- 球队页、BF Next 赛程、Titan/Nowscore H2H 和赛前指数按各自的 fixture/team/match 键缓存，不受自动/指定期模式影响。

## 缓存键

- `sfc:https://trade.500.com/sfc/?expect=26120`
- `jczq:current`
- `odds_xml:current`
- `detail:{fixture_id}`
- `team:{team_id}`
- `bf_next:{yyyymmdd}`
- `h2h_desktop:{match_id}`
- `h2h_mobile:{match_id}`
- `movement_mobile:{match_id}`
